Gimba

Real-time customer data platform

Apps send events; Gimba stitches them into one profile per customer, keeps segments current, and calls the app back when someone enters or leaves a segment. Gimba decides who. The app decides what happens, and Gimba reports on the result.

Multi-tenant and fully reactive, with no blocking calls in the hot path. Profiles can be replayed from the append-only event log, and projections update off Kafka.

Wallet Microservices

Distributed digital wallet

A rand wallet as an API gateway and four reactive Spring Boot services. Every money movement is a balanced journal in a double-entry ledger, events leave through a transactional outbox, and money calls are idempotent. Shipped with ArgoCD GitOps onto Terraform-provisioned AWS.

SpazaAPi

Commerce and delivery for spaza shops

Online ordering and delivery for South African spaza shops: an API gateway and six Spring Boot services coordinating through Kafka, idempotent payment-provider webhooks, and deliveries that recover from driver timeouts and offline drivers. Runs on Amazon EKS in Cape Town.

How they ship

Every service is Terraform-provisioned and runs on AWS, each deployed a different way: ArgoCD GitOps to EKS, Kubernetes manifests to EKS, and a Dockerized service on EC2. The infrastructure lives in its own repo, separate from the application code. Read the cloud deployments write-up.
