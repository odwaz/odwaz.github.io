Gimba

Real-time customer data platform

Apps send events; Gimba stitches them into one profile per customer, keeps segments current, and calls the app back when someone enters or leaves a segment. Gimba decides who. The app decides what happens, and Gimba reports on the result.

Multi-tenant and fully reactive, with no blocking calls in the hot path. Profiles can be replayed from the append-only event log, and projections update off Kafka.

Wallet Microservices

Distributed digital wallet

A rand wallet as an API gateway and four reactive Spring Boot services. Every money movement is a balanced journal in a double-entry ledger, events leave through a transactional outbox, and money calls are idempotent. Shipped with ArgoCD GitOps onto Terraform-provisioned AWS.

Agent orchestration

Coding agents work inside plain, deterministic code. The orchestrator decides who asked, which repository, which files and whether the tests pass. It calls a model at exactly two points, and a person approves at three.

Every handoff to a model goes through the orchestrator, and nothing a model returns reaches your repository untested. The orchestrator stops and publishes nothing if the issue, the approval or the default branch changes mid-run.

agent-orchestrator

From GitHub issue to draft pull request

Five GitHub Actions workflows in Python, and three human approvals: the spec merge, the agent-ready label and the PR merge. The GitHub App key and model keys stay in the orchestrator, which mints short-lived tokens per job. Each model key reaches only the one job that uses it.

Guard rails: only writers can trigger a run, and that is re-checked on every run. Each approval gets one run, with no automatic paid retries. Build files, workflows and config are always out of scope. The source is private. Email me for a walkthrough.
