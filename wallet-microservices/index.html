Wallet Microservices

A rand wallet built as five Spring Boot services behind an API gateway, fully reactive with WebFlux and R2DBC. Every money movement is a balanced journal in a double-entry ledger, and every event about it leaves through an outbox written in the same transaction. It ships through GitOps onto Terraform-provisioned AWS.

Java 17 Spring WebFlux R2DBC ArgoCD GitOps Solo project: services, UI, infra and pipeline

Services

Services share a PostgreSQL server but each owns its tables, and a shared-dtos module keeps the contracts between them from drifting.

What it does

sign-in with one-time codes

auth-service checks the password, then issues a JWT only after a one-time code is verified. Signing up creates the login and the user's ZAR wallet in one call.

top-ups, transfers, withdrawals

Money moves between wallets by alias. Every operation posts a balanced journal and updates the cached balance in the same transaction.

history and notifications

transaction-service keeps the history and forwards events to the CDP; webhook-service notifies subscribers. Neither sits in the path of a payment.

CDP integration

Wallet activity is sent to an external customer data platform over its published HTTP contract. When the CDP puts a customer in a segment it calls back; wallet-service verifies the signature and stores the result for the app to use.

Engineering highlights

Where a wallet is easy to get subtly wrong, and what this one does about it.

A double-entry ledger, not a balance column

Every money movement is a journal of postings that must sum to zero, or the whole journal is rejected, so a half-applied transfer can't reach the ledger. The wallet balance is a cache of the ledger, and GET /wallets/{id}/reconcile checks one against the other.

Events leave through a transactional outbox

The event describing a payment is written in the same database transaction as the payment, then drained to transaction-service by a publisher. Delivery is at-least-once, so the consumer dedupes on the transaction ID and nothing is lost if a call fails mid-flight.

Idempotent money calls

Top-ups and transfers accept an Idempotency-Key. A retried request returns the original result instead of moving money twice, and a request that arrives while the first is still running is told so rather than raced.

Success has to be proven

A database driver mismatch once made every write die with a JVM-level error that left the reactive chain empty, and WebFlux turned that into a 200. The fix moved to the driver Spring Boot manages, and the controller now treats an empty result as a failure, with tests that pin both cases.

Callbacks it can trust

The CDP signs each callback with Ed25519 over the raw body. wallet-service verifies it with the CDP's public key, which is shared out of band, so the gateway can let callbacks through without a user token and nobody else can forge one.

GitOps delivery with ArgoCD

GitLab CI builds and tests, Trivy scans the images, and ArgoCD syncs the desired state from Git to the cluster. Conditional workflows skip services that didn't change.
